# PR #145 integrated recovery verification — 8 October 2026

The [review finding](https://github.com/c933103/openrailwaystyle/pull/145#discussion_r4213750669) is valid when recovery happens **without idle**. Idle already calls `updateStatus`. A callback inside `noteSourceData` would run before app error bookkeeping is cleared, so the app now updates status after the entire transaction. Actual metadata/tile success is required; `isSourceLoaded` alone is insufficient. Remaining failed tiles and unrelated errors retain their warnings. Before style readiness, status text updates without querying rendered features.

Five app-level regression tests fail before the fix and pass afterward. They exercise one-tile recovery without idle, early style events, partial recovery, loaded-but-errored sources, unrelated errors, metadata success, duplicate events, cancellation, source replacement and disposal. Timers are controlled; these event sequences initiate no additional retry requests.

## Arbitrary world-copy visibility after `3c84d53`

[Codex P2](https://github.com/c933103/openrailwaystyle/pull/145#discussion_r4222970900) identifies a valid controller limitation: testing only tile offsets −360°, 0° and +360° discards visible failures beyond those copies. The precise browser reproduction differs from the proposed repeated-pan explanation. In existing Chromium 151 with production MapLibre 5.24.0, completed `panBy` calls normalized the center, but `jumpTo` retained centers at ±720° and ±1080°. Atlas also accepts finite unwrapped longitude in its view hash. An empty local MapLibre style with `renderWorldCopies:true` provided actual bounds to the actual recovery controller; no provider requests or renderer mocks were involved.

At zoom 2, latitude −20°, an 800×600 viewport centered at 720° returned west/east **649.6875° / 790.3125°**. A failed canonical tile `2/2/2` was discarded before correction and retained afterward. Results for centers 0°, 360°, 720°, 1080°, −720°, −1080° were respectively **retained, retained, discarded, discarded, discarded, discarded** before, and **retained in every case** afterward. Each retained failure has one pending timer. This demonstrates supported unwrapped bounds, not a claim that the completed-pan test reproduced them.

The correction normalizes the finite viewport interval and checks whether an integer world offset places the canonical tile across it. It does not enumerate or load world copies. Antimeridian intervals, inclusive touching boundaries and viewports at least 360° wide are handled explicitly. Latitude is still checked first; unavailable/nonfinite longitude cannot establish exclusion, consistent with retaining failures when bounds are unavailable. Missing bound accessors are treated as unknown rather than throwing. Source replacement, disposal and off-screen pruning are unchanged, as are the existing timer and all request/cooldown bounds.

Four new controller regressions cover ±100 worlds, positive/negative intermediate worlds, antimeridian crossings, edge contact, one/multiple-world-wide viewports, off-screen longitude and latitude, source retirement and unknown/nonfinite bounds. Existing deadline and numeric/date Retry-After regressions remain. The world-copy regression fails before correction and passes afterward.
