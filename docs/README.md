## Where new information belongs

Keep the root README to the project purpose, live-map link, short feature summary
and entry points. Put instructions and reference details in the focused pages
above, linking between them instead of copying the same explanation.

Document current behaviour beside the relevant topic. Keep work proposals and
bugs in GitHub issues, and implementation discussion, review notes and validation
results in pull requests. Preserve durable design rationale in the relevant
reference page; use Git history for the chronological record. Upstream history
belongs in its own page, separate from current Atlas features.
