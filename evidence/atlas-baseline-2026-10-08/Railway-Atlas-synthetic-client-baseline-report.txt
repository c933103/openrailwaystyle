State and measurement definitions:
cold_browser: New Chromium process, new nonpersistent context and page for each pair; empty app state. OS/file cache not flushed. Startup begins at navigation, excludes browser launch/asset preparation.
warm_browser: Second navigation in same browser/context/page after initial navigation and pan sequence. Retains browser session/OS state, creates new document/app instance. Playwright routing disables HTTP cache in BOTH cases; this is not a warm HTTP-cache benchmark.
cached_pan: Reset to starting center after first pan, wait for idle, repeat same forward pan in same document; tests retained app/MapLibre tile caches.
ready: MutationObserver timestamp for body data-map-ready=true using performance.now() since navigation time origin.
idle: Actual MapLibre idle event. PanBy([512,0],duration=0), starting z14 centered [114.4,30.55]. Each pan bounded to 20 seconds.
main_task_duration_s: CDP Performance TaskDuration delta. Default time domain was used; threadTicks was not selected. Treat as task duration, NOT an independently measured main-thread CPU time. Legacy samples.json uses a misleading CPUSeconds suffix for Task/Script/Layout duration fields; canonical measurements and CSV correct the label.
observed_process_cpu_s: Sum of SystemInfo.getProcessInfo cpuTime deltas across 7 browser-related processes/all their threads. No new/lost PIDs in recorded phases. Includes GPU/software rendering. Collection interval brackets phase and includes CDP/monitoring overhead; not utilization derived from ready time.
heap: JSHeapUsedSize/TotalSize for the inspected page/main isolate after each phase; excludes worker heaps; no forced GC.
rss: Sum of /proc/PID/status VmRSS sampled for 7 browser processes after phase. Shared pages may be counted repeatedly; not unique memory, not peak memory.
responsiveness: requestAnimationFrame callback gaps wholly within phase; nearest-rank p95; not compositor FPS or input latency. Pan has 4-7 intervals and cached pan 2-5. Long tasks use main-frame PerformanceObserver longtask entries whose start is within phase.
bytes: Network.loadingFinished encodedDataLength is the CDP encoded response counter including protocol overhead; not an exact wire capture. Intercepted values are synthetic counters, not upstream traffic. Network.getResponseBody byte length is decoded HTTP body size; application gzip MVTs without Content-Encoding remain compressed.
phase_attribution: Requests assigned to phase when requestWillBeSent arrives; setup gaps/metric reads can be attributed to adjacent phase. Only page-target CDP Network events observed.
unavailable: Three first-party worker scripts and one blob worker per startup had request-start events but no page-target response/loadingFinished events. Their encoded/body sizes and final status/cache/failure are unavailable. All startup byte sums are known-byte lower bounds. Wire bytes, worker-target full ledger, per-thread true CPU, user/system CPU split, peak/unique process memory, compositor frames, user input latency and warm HTTP-cache measurements are unavailable.
blocked: No loadingFailed/blocked events in observed page-target records. External/provider requests fulfilled locally; no upstream delivery. Browser DNS restricted to loopback; service workers disabled. Worker-target final statuses unavailable. This is not a packet-capture count.
cache: Five servedFromCache events each startup are data: SVGs; HTTP disk cache and service worker flags are zero observed. Do not count data: hits as HTTP cache savings.
