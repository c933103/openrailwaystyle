# Contribution guidelines

Thanks for your interest in our project. Contributions are welcome. Feel free to open an issue with questions or reporting ideas and bugs, or open pull requests to contribute code.

It's important to us that we have a welcoming and respectful environment for everybody here. Please be kind.

By submitting a contribution to this repository you agree that you do this under the license of the repository and certify that you have all the rights to do so.

## Development

Follow the [development guide](docs/development.md) for setup, source layout,
published map data and validation. Explain the problem, resulting behaviour and
relevant checks in your pull request. Include generated style changes when editing
the style builder.

## Documentation

Use the [documentation index](docs/README.md) to find the right home for new
information. Keep the root README as a short project entry point. Update user
instructions, rendering and language references, or maintenance procedures in
their focused pages when behaviour changes. Link to the detailed explanation
instead of duplicating it.

Use issues for proposals and bugs, and pull requests for implementation discussion
and review results. Move lasting design rationale into the appropriate reference
page. Keep upstream history separate from current Atlas documentation.

Check relative links and heading anchors when moving text, preserve source
credits and data limitations, and run `git diff --check`.
